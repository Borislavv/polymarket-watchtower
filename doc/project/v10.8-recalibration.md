## 3. Threshold recalibration

The v10.8 default change is conservative: the **concentration gate**
does the heavy lifting at the alert-persistence layer, NOT a
threshold cliff. The notional/multiplier ladder defaults in
`presets/prod.env.template` remain (operator-tunable). The new
behaviour is:

- **First alert per (wallet, event):** clears with current
  thresholds. Operator gets it.
- **Subsequent alerts in the WALLET_ALERT_COOLDOWN window (default 6h):**
  must clear `previous_max_notional × ACCUMULATION_ESCALATION_FACTOR`
  (default 2×) — otherwise dropped silently.
- **Per-event cap:** after `EVENT_ALERT_CONCENTRATION_LIMIT=3`
  alerts on the same event in `EVENT_ALERT_CONCENTRATION_WINDOW=24h`,
  the (N+1)th alert must clear `prev_event_max_notional ×
  REPEATED_EVENT_THRESHOLD_MULTIPLIER` (default 2×).
- **Warning/Critical bypass.** The gate only applies to Info-tier
  alerts. Severity ≥ Warning ships always.

**Simulated v10.8 impact on the 4-day live data**:
- 47 alerts would have been "first alert" — pass.
- 6 alerts (10.5%) would have failed wallet escalation.
- 4 alerts (7%) would have failed event concentration.
- **Estimated alert-volume reduction: ~10-17%** for the existing 4
  days, ~30-40% on the day-20 spike specifically.

## 4. Concentration gate implementation

`internal/app/usecase/concentration/concentration.go`:
- `Gate.Evaluate(ctx, Candidate, AlertHistory)` is pure (no I/O).
- Two SQL queries on `polymarket_alerts` (event + wallet window).
- Wired in `detect.Loop.persistAlert` BEFORE `TryCreatePending` —
  suppressed alerts leave no DB row and no dedup key.
- Metric: `watchtower_concentration_suppressed_total{reason}`.
- Tests: 7 unit tests + behavioural pin against the live audit data.

## 5. Sentinel rename (v10.8 PascalCase)

The v10.8 operator-facing wire format is the PascalCase family:

| v10.8 wire | Canonical Code | Meaning |
|---|---|---|
| `AiAnsweredNotFoundNoticeable` | `CodeNoNoticeableEdge` | nothing actionable |
| `AiAnsweredAlreadyPriced` | `CodeAlreadyPriced` | edge gone |
| `AiAnsweredContextStale` | `CodeContextStale` | refuse to analyse |
| `AiAnsweredOnlyResolutionBlocked` | `CodeOnlyResolutionBlocked` | wait-for-election day only |
| `AiAnsweredInsufficientData` | `CodeInputInsufficient` | malformed input |

The legacy `AI_NO_NOTICEABLE_EDGE` SCREAMING_SNAKE forms remain
parseable for backward compatibility. The `PromptAppendix` constant
leads with the new family. Either is acceptable; pick one and use
it consistently.

## 7. Unified-intelligence collapse plan (v10.9 — not in this PR)

The audit identified 5 separate AI surfaces:
1. Market intelligence 2h
2. Daily political intel
3. Annotation ranking AI
4. Prediction AI refresh
5. Catalyst importer AI

The v10.8 spec calls for collapsing these into ONE unified
evaluator. That is a substantial architectural change and is
**deferred to v10.9**:

- The v10.9 evaluator runs ONCE per cycle (default 4h).
- It receives a deterministic shortlist of candidates (markets +
  annotations + catalyst changes) and either:
  - returns interesting markets with reasons, OR
  - returns `AiAnsweredNotFoundNoticeable` and nothing ships.
- It produces a single Telegram message — not 5 separate ones.
- Daily intel becomes a once-per-day summary of the day's
  evaluator outputs, not an independent AI call.
- Annotation ranking becomes a deterministic pre-filter, not a
  separate AI.
- Catalyst importer keeps its AI but its output feeds the
  evaluator, not Telegram.
- Prediction refresh becomes a sub-routine of the evaluator,
  triggered only when the evaluator surfaces a prediction-worthy
  market.

This requires:
- A new `unifiedintel.Worker` that consumes the existing data
  sources.
- Removal of the per-surface AI scheduling.
- Migration of `polymarket_market_intelligence_reports` schema to
  carry richer output (regime + selected markets + sentinel code).
- A v10.8.1 sub-step: dry-run the new evaluator on the existing
  candidate set and compare to the 5-surface output.

## 8. Blocked-markets rebroadcast policy (v10.7 already enforces)

The v10.7 worker already drops `watching → blocked` Telegrams whose
only blocker is a resolution-day catalyst. v10.8 keeps this and
adds the per-event concentration cap so even legitimate blocked
re-alerts can't spam the same event.

When the v10.9 unified evaluator lands, blocked markets become a
section of the unified report (re-alerted every 3-6h ONLY if there
is fresh operational relevance — fresh repricing, new catalyst,
news change).

## 11. Operator opt-outs

If any v10.8 default is too aggressive in steady state:
- `EVENT_ALERT_CONCENTRATION_LIMIT=0` disables the concentration
  gate entirely (legacy v10.7 behaviour).
- `AI_MARKET_INTELLIGENCE_INTERVAL=2h` restores legacy 2h cadence.
- `PREDICTION_SEND_RESOLUTION_ONLY_BLOCKED=true` restores legacy
  prediction Telegrams (already a v10.7 flag).
- `MARKET_INTEL_SUPPRESS_ON_SENTINEL=false` makes marketintel ship
  sentinel results as fallback messages.

All knobs default to the v10.8 safe values.
