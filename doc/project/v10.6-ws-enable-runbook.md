# v10.6 — WebSocket Production-Test Enablement Runbook

WS_ENABLED=true is now the default. Conservative hot-mode caps
(25 markets / 50 tokens) keep the first production run small and
reversible. Polling + backfill + reconciliation remain canonical
source of truth.

## Pre-flight (operator)

1. Confirm Postgres is reachable; migrations through `00024` apply
   automatically on app boot.
2. Confirm Telegram chat id + bot token are wired.
3. Confirm OpenAI API key is wired (alerts + intel still depend on
   it; WS does NOT).
4. Verify `WS_ENABLED=true`, `WS_MAX_MARKETS=25`, `WS_MAX_TOKENS=50`
   in your active env file. Do NOT set `WS_ALLOW_LARGE_SUBSCRIPTION=true`
   for this first cycle.

## Smoke check (≤ 3 minutes)

Outside the daemon, sanity-check the WS path with the CLI:

```bash
# Live read (no persist, no DB):
go run ./cmd/cli ws-smoke \
  --tokens <CLOB_TOKEN_ID_1>,<CLOB_TOKEN_ID_2> \
  --duration 60s

# With persistence (writes to ws_events / live_market_state / queue):
go run ./cmd/cli ws-smoke \
  --tokens <CLOB_TOKEN_ID_1>,<CLOB_TOKEN_ID_2> \
  --duration 60s --persist --dsn "$POSTGRES_DSN" --reconcile
```

Expected:
- Endpoint: `wss://ws-subscriptions-clob.polymarket.com/ws/market`.
- Subscribe payload: `{"assets_ids":[…],"type":"market"}`.
- At least one `book` and one `price_change` (or `last_trade_price`)
  event from a live political/macro market within 60s.
- No `decode_errors`. No `drops`. Zero or one reconnect over 60s.

Validated 2026-05-21:
```
endpoint:    wss://ws-subscriptions-clob.polymarket.com/ws/market
tokens:      3
duration:    1m0s
events-by-type:
  book                   3
  last_trade_price       2
  price_change           4
  heartbeat              5
  unknown                1
```

## Production-test enablement (operator runs)

1. Restart the stack with the v10.6 env values.
2. Wait 30 s. Tail the daemon log for one of:
   - `polymarket ws: subscribed` (success).
   - `realtime ws: disabled` (mis-configured — `WS_ENABLED=false`).
   - `validate config invariants` (cross-field belt tripped — fix and
     restart).
3. Observe Grafana row "Realtime WebSocket (v10.4)" for 10-15 minutes.

## Observation metric set (PART 7)

| Metric | Threshold | Action |
|---|---|---|
| `watchtower_ws_connected` | should be `1` | flip to 0 ⇒ check `ws_reconnects_total` |
| `watchtower_ws_subscriptions` gauge | matches `WS_MAX_TOKENS` after first sub refresh | 0 ⇒ selector returned empty (DB or upstream issue) |
| `watchtower_ws_events_total{type=book|price_change|last_trade_price|best_bid_ask}` | growing | flat for >5 min ⇒ stream may be dead, check connected |
| `watchtower_ws_decode_errors_total{type}` | < 5/min | sustained > 5/min ⇒ Polymarket added a new field; investigate |
| `watchtower_ws_events_dropped_total{reason}` | 0 sustained | non-zero ⇒ reduce `WS_MAX_MARKETS` or raise `WS_EVENT_BUFFER` |
| `watchtower_ws_reconnects_total` | < 3 / 10 min | sustained > 3 / 10 min ⇒ degrade, then disable |
| `watchtower_ws_gap_recoveries_total{status}` | non-zero only when polling diff > 0 | failed gap-recovery means reconciliation is sick |
| `watchtower_realtime_work_enqueued_total{reason}` | grows in lockstep with events | 0 enqueues with >0 events ⇒ DB write path broken |
| Worker `workerguard` overlap skips | rare | persistent overlap skips ⇒ a worker is slower than its interval |
| Telegram sends rate | unchanged vs baseline | a spike from WS ⇒ a leak into alerting (forbidden); roll back |
| AI calls/min by surface | unchanged vs baseline | likewise — WS must not influence AI cadence |

## Rollback playbook

If any line in the table above turns red:

```bash
# 1. Disable WS without code change:
echo "WS_ENABLED=false" >> .env.override
# 2. Restart the stack.
# 3. Polling + backfill + alertsender keep running unchanged.
# 4. ws_events / live_market_state rows REMAIN — no cleanup needed.
```

For a permanent rollback, set `WS_ENABLED=false` in the active env
file (`presets/prod.env.template` ships with the v10.6 default, so
overrides go in your deployment-specific env file).

## What is NOT in scope for v10.6

- Prompt tightening across surfaces — deferred to v10.7.
- Alert/prediction efficiency calibration — deferred to v10.7.
- Strategy threshold retune (p99 vs p95) — deferred to v10.7.
- Volume-tier expansion of `hot` mode beyond the v10.6 prioritised
  set — deferred to v10.7 with operator evidence.
- AI / Telegram cadence changes — explicitly out of scope.

## What is NOT in scope for ANY WS PR

- Direct WS → AI path (forbidden; architecture test pins this).
- Direct WS → Telegram path (forbidden; architecture test pins this).
- WS-driven severity inference (forbidden; strategy layer reads
  side_source and downgrades when only WS evidence exists).
- WS replacing polling (forbidden; polling is canonical source of
  truth, WS is a trigger accelerator).
